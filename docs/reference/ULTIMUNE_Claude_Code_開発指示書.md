# Claude Code 開発指示書
# ULTIMUNE | Customer Journey & Golden Path Analytics

## 0. 役割・ゴール
あなたはマーケティングデータ分析とWebアプリ開発に精通したシニアフルスタックエンジニアです。資生堂アルティミューンの個票CSVと分析Excelを使い、**実データから動的に集計できる**カスタマージャーニー分析Webアプリを完成させてください。モックアップのみで終了しないこと。

アプリ名：**ULTIMUNE | Journey Analytics**。デザインは**Media Flowのメジャメント**を参考にした、白背景・シンプルな業務用分析ダッシュボード。**AI Cockpit・チャットUIは不要**。Media Flowのスクリーンショットが別途提供されれば、それをデザインの優先参照元にしてください。添付のGolden Path画像はフロー描画の参考です（数値は転用しない）。

## 1. 入力ファイル
プロジェクトの `data/raw/` に以下を置く想定。実際のファイル名・列・シートはコードで検査してから読み込むこと。

1. `1stPTD分析_パス分析 (1).csv`：個票の正本。`年代`、`結果`、`タイプ分類`、`開始期`、`日数`、`行動数`、`行動01`〜`行動25`。1行1人。確認値：全12,430人、購入者2,430人、非購入者10,000人。18–29歳：購入230人／非購入5,000人、30–49歳：購入2,200人／非購入5,000人。平均行動数約16.31、平均日数約23.38は検証目安であり、表示は必ず再計算する。
2. `20261006_資生堂｜1stPTD分析_パス分析結果 (2)(1).xlsx`：`全パターン`、`マスタ`、意思決定期間、パス優先度（個別項目／カテゴリ、行動発生時期／検討期間）の既存集計。CSVと`全パターン`を二重計上しない。`マスタ`を分類に利用し、既存集計を検証に利用。
3. `資生堂1stPTD追加集計.xlsx`：年代別の個別変数出現率・平均発生時期、悩み系KW起点の2・3接点パス。起点行動分析の検証用。
4. `【資生堂】購買パス分析_行動変数加工_06_競合ブランドサイト一覧以外更新.xlsx`：検索KW、外部サイト、bSサイト、タレント／RP記事、競合検索等の加工定義。既存マスタとの不一致は一覧化し、勝手に上書きしない。
5. Golden Path参考画像：円形ノード・曲線エッジ・横並びステップの参考。

CSVはUTF-8 BOMなどの文字コードに対応し、Excelはopenpyxl/pandasで読み込む。列名の表記揺れを検出し、欠損・未知のカテゴリは隠さず表示。**非購入者のD−nは購入日基準ではない**ため、基準日定義を確認できない場合は「基準日」と表記する。`日数`も意思決定期間と断定せず、定義未確定なら「観測期間」と表記する。

## 2. 技術構成
- Frontend：Next.js、React、TypeScript、Tailwind CSS、shadcn/ui
- フロー：React Flow（@xyflow/react）＋カスタムノード／エッジ、必要ならD3でレイアウト
- グラフ：Recharts
- Backend：Python、FastAPI、pandas、openpyxl
- 中間データ：Parquet、必要ならSQLite
- 共通フィルタ：Zustand等で状態管理
- ローカルで実行可能にし、README、依存関係、起動コマンド、テストを整備。外部LLM APIは不要。

## 3. UI共通仕様
左側固定サイドバー、上部ページタイトル／データ更新日時／エクスポート、共通フィルタ、KPIカード、中央の大きな分析グラフ、下部の詳細テーブル。白・グレー中心、アクセントカラーはMedia Flowメジャメントの参考画像があればそれに合わせる。チャットパネルやAI Cockpitは設置しない。

共通フィルタ：
- 年代：全体／18–29歳／30–49歳
- 結果：購入者／非購入者／全体（Golden Path初期値は購入者）
- 人の期間：全期間／0–7日／8–14日／15–21日／22–30日／カスタム範囲
- 行動発生時期：全期間／D−30〜15／D−14〜8／D−7〜0／カスタム（人の期間とは別）
- 粒度：個別変数／分析カテゴリ／大分類
- ステップ数：2〜10のプリセット＋最大25までの任意値（初期値5）
- 連続パス／順序保持パス（初期値は連続）
- 同一行動：すべて保持／連続重複統合／初回のみ
- 表示ノード上位数3〜15、最小人数、最小遷移率、「その他」表示切替
- フィルタリセット、PNG／SVG／CSVエクスポート。画面遷移後も共通フィルタを保持。

## 4. ページ構成と要件

### 01 データ概観（Overview）
KPI：総人数、購入／非購入人数、年代別人数、平均・中央値の行動数、平均・中央値の観測期間、ユニーク個別変数数・カテゴリ数。行動数ヒストグラム、期間分布、タイプ分類構成比、行動カテゴリ一覧（人数・経験率・平均D−n・購入者／非購入者差）。欠損・マスタ未対応・D−n解析エラー・25列上限到達などデータ品質も表示。

### 02 Golden Path（最重要）
横方向に `STEP 1 → STEP 2 → ... → Outcome`。円形ノードはカテゴリ名と経験率を表示し、**ノード面積を経験率に比例**させる（半径は経験率の平方根に比例、最小最大サイズあり）。エッジは曲線＋矢印、**太さは遷移人数**に比例、ラベルは条件付き遷移率。ホバーで人数・分母・経験率・平均発生時期等を表示。

表示モード：①行動01からの先頭nステップ、②最後の観測行動から逆算した末尾nステップ、③任意起点からnステップ、④全25ステップ横スクロール。**先頭5ステップの後に直ちに購入したかのような図は禁止**。購入Outcomeは最終観測行動の後にのみ置く。非購入者の終端は「非購入／観測終了」。途中で打ち切る場合は「後続行動あり」を適切に示す。

ノードクリック：そのステップ・行動を通った人に絞り込み、後続を再集計。エッジクリック：その遷移を経験した人に絞り込み。複数選択：選択した**完全パス**を実際に経験したユニーク人数・率を表示。下段に主要2／3／5ステップパス、購入者特徴パス、選択パス詳細を表示。ノードを上位数に間引いても集計分母は変えない。

### 03 パス比較
左右2カラムで同じ条件のフローを比較。プリセット：購入者vs非購入者、18–29歳vs30–49歳、短期vs長期、任意A/B。ノード位置・色・サイズスケール・ステップ数を揃える。経験人数、経験率、差pt、倍率、条件付き遷移率差、平均行動数・期間差を表示。差分ランキングも用意。ゼロ除算は「算出不可」、少数セル（例5人未満）は注意表示。購入者に多いことを購買因果効果と呼ばない。

### 04 時系列分析
D−30〜D−0のカテゴリ別ヒートマップ、日別経験人数／率の推移、D−30〜15・D−14〜8・D−7〜0のランキング、人の観測期間別の比較。行動発生時期フィルタ後に隣接させたパスは「期間内抽出後の隣接」と明記し、元ログでの真の連続パスと区別する。

### 05 起点行動分析
検索可能な起点セレクト（肌悩み／肌根本悩み／肌表面悩み／UTM指名検索／資生堂指名検索／資生堂オンライン／@cosme／美的.com／mybest／EC等、**実マスタに存在する項目のみ**）。起点→2番目→3番目を初期表示し、2〜10ステップまで変更可能。起点の初回出現／最終出現／全出現を切替。直後の行動／次に指定カテゴリが現れる行動／指定日数内の後続行動を切替。全出現モードではイベント件数とユニーク人数を区別。

表示指標：起点単体経験率、起点経験者を分母とした2接点率、2接点経験者を分母とした3接点への条件付き率、全対象者を分母とした完全パス経験率。`資生堂1stPTD追加集計.xlsx`の悩み検索起点結果と照合し、定義が違う場合は無理に一致させず差分理由を表示。

### 06 パス詳細探索
起点・終点・経由・ステップ数・年代・結果・期間・人数閾値で検索。テーブル：パス文字列、経験人数、経験率、購入者／非購入者率、差pt、倍率、平均期間、平均行動数、平均発生時期。行クリックで詳細パネルに匿名の実行動例、カテゴリ変換前後、ステップ別時期、セグメント比較を表示。Golden Pathへの遷移・ハイライトを可能にする。

### 07 データ・変数定義
CSV／Excelアップロード、読み込み状況、シート・カラム・データ型、欠損、個別変数→分析カテゴリ→大分類の対応表、元シート・加工ルール、未分類・不一致一覧。再読み込み、集計キャッシュ無効化。元ファイルは上書きしない。データ品質検査の結果を表示。

## 5. 集計ロジック（厳守）

### 正規化
CSV1行を1人とし、内部で一意なperson_idを生成。
- `persons(person_id, age_group, purchase_status, journey_type, start_period, duration_days, recorded_action_count)`
- `events(person_id, step_index, days_before_reference, raw_action, individual_variable, analysis_category, broad_category, repeat_index)`

`D−24｜外部サイト_大衆向けEC_Yahoo！ショッピング_1回目` のような文字列を解析。Unicodeのマイナス・全角区切り・日本語・アンダースコアを考慮。**単純にアンダースコアで全分割してサイト名を壊さない**。接触回数接尾辞は末尾から認識。解析不能時はraw_actionを保持してエラーを記録。空白行動列は欠損扱い。行動順序と繰り返しは初期状態で保持。

### 分母・指標
- **行動単体経験率**＝行動を1回以上経験したユニーク人数÷フィルタ対象者数
- **ステップnのノード経験率**＝ステップnで当該行動を経験した人数÷フィルタ対象者数
- **ステップn到達者内構成比**＝ステップnで当該行動を経験した人数÷ステップn到達者数
- **A→B遷移率**＝当該定義でAからBへ遷移したユニーク人数÷Aの該当ステップ到達者数
- **完全パス経験率**＝指定したA→B→C…を実際に満たすユニーク人数÷フィルタ対象者数
- **経験率差pt**＝セグメントA経験率−セグメントB経験率
- **倍率**＝A経験率÷B経験率（Bが0なら算出不可）

同じ人が複数回同じパスを経験しても、人数ベースは1人。イベント回数ベースは別表示。**A→B率とB→C率の積からA→B→C率を作らず、個票から直接計算**。連続パスと順序保持パスは別の集計モードとして実装し、画面で明示。

購入者／非購入者のサンプル構成から「市場全体の購買率」を算出しない。既存Excelの推計UTM購買率は元の推計方法を確認したうえで別指標として扱う。SHAP値は別データが提供された場合のみ追加し、パス経験率や購買寄与と混同しない。

### 完全パスと図の整合性
各ノード・エッジは個票に存在する遷移のみ。各ステップの最多カテゴリを単に結んだ架空の「ゴールデンパス」を生成しない。エッジを辿った完全パス人数は、選択経路に沿う個票を改めて絞って計算する。全体の最多経路と購入者に特徴的な経路を別ランキングにする。

## 6. API設計（例）
- `GET /api/overview`：母数・分布・品質
- `POST /api/paths/graph`：フィルタ、モード、ステップ数、ノード／エッジ集計
- `POST /api/paths/compare`：A/B比較
- `POST /api/paths/entry`：起点行動パス
- `POST /api/paths/search`：パス検索
- `POST /api/timeline`：日別集計
- `GET /api/dictionary`：マスタ・変数定義
- `POST /api/upload`：入力データ差し替え
- `GET /api/validation`：既存Excelとの照合

APIレスポンスには必ず、対象者数、指標の分母、人数、率、適用したパス定義・フィルタ、欠損／打ち切り情報を含める。キャッシュキーにはすべての集計条件を含める。

## 7. 表示・操作
React Flowでズーム／パン／横スクロール、ノード・エッジホバー／クリック、経路ハイライト、フィルタ解除。ノードサイズは面積比例、エッジ幅は遷移人数比例。エッジ交差を最小化し、選択経路以外を薄く表示。SVG／PNGは**図全体**を出力（表示中のビューポートのみで切らない）。CSVは数値・分母・集計条件を含める。ローディング・対象なし・計算不可・データエラーを区別する。
